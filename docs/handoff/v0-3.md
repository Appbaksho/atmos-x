## How screens use it

- **The context comes first.** Every hook reads `useDataContext()`, which holds `ready`, `ns`, `kind`, `userId`, `lang` and `prefs`. Queries stay disabled until `ready` is true; it flips on the client after prefs and the session load. The context follows `prefs-store` through `subscribePrefs`, so V0-1's prefs context must write through `setPrefs()`. That covers `presentation`, `lang` and the rest.
- **Errors (`@/lib/data/hooks` re-exports them):**
  - `GuestRestrictedError` (`code: 'auth.guest_restricted'`) → call `requireAccount()`. Use `isGuestRestricted(e)` to check.
  - `RateLimitedError` (429, `retryAfter` in seconds) → show the "limit reached" toast.
  - `DataError` → `ErrorState` with retry. `server.not_available` means the endpoint isn't deployed yet; `network.error` means offline.
  - 4xx errors are never retried (`shouldRetry`).
- **Location-taking hooks take the point from the caller.** In Presentation mode, pass `DEMO_POINT`, which reads `NEXT_PUBLIC_DEMO_LAT/LNG` and falls back to 23.759, 90.359. Passing `null` disables the query.
- **Photos:** `photo_url` is either an `idb:<ns>:photo:<id>` key or a normal URL. Render it with `const src = usePhotoUrl(photo_url)`, which creates an object URL and revokes it on unmount. http, data and blob URLs pass through unchanged.
- **Query keys:** `qk.*` in `hooks/keys.ts`. Server data lives under `['atmos','server',…]` and device data under `['atmos','local',ns,…]`. The helpers `invalidate.afterAction / afterTreeCheck / afterTeams / goals / namespace(qc, ns)` and `invalidateScore(qc, ns)` cover the common refreshes. The mutations below already invalidate what they touch.

### Log action flow (`useLogAction`)

1. The photo is decoded once. A ≤ 1600 px JPEG blob is stored at `idb:<ns>:photo:<id>`, and a ≤ 768 px JPEG data URL is sent in a `VerifyPhotoRequest`. The request's `target` is `input.target`, falling back to the goal's zone centroid.
2. The log is stored with the server's `status`. If the request fails, is unavailable or is rate limited, the log is stored as `pending` with `reason_code` set to `unavailable`, `rate_limited` or `no_photo`.
3. Points come from the action-types table. Pending points count as provisional.
4. **Goal progress** (verified only): `modeled_c −= cooling_c / zone_area_km2` (minimum 0.05 km²) and `progress = modeled ÷ target`. Milestone notifications fire at 25/50/75/100 %.
5. A `verification` notification is created, with `screen: 'S15'` and `params.id`.
6. `plant_tree` creates `min(qty, 20)` trees. The planting photo counts as the first photo.

### Ask (`useAskStream`)

`send()` does the following:
1. It consumes the local quota: 5 a day for guests, then `GuestRestrictedError`; 30 a day for accounts, then `RateLimitedError`.
2. It builds `client_state`: profile kind, unit, farmer mode, up to 20 trees, the active goal, and `visible`. Long strings are cut first, then `visible` keys, then trees, to stay ≤ 6 KB.
3. It sends the last 6 turns as `history`.
4. It reads the SSE stream with fetch + `ReadableStream` + `TextDecoder`.

On the assistant message, `warning`, `sources` (deduplicated) and `actions` (max 2, navigate only on tap) arrive as events. `done.remaining_today` lowers the local counter. Errors during the stream end up on `message.error`; 429 and guest-restricted errors are also rethrown by `send`.

## Presentation mode

- **Turning it on.** `usePresentation().enable()`, or any `setPrefs({presentation: true})` call (Settings toggle, `?demo=1` handled by V0-1), switches the data namespace to `demo`. On the first switch it loads Nadia's story from `seed/story.json`:
  - profile
  - the Asad Gate goal (−1.5 °C by 2 Oct 2027, 38 %, Hall Rooftop Crew)
  - 4 trees (Shanti, Megh and Chhaya are neem trees planted 3 days ago; **Beguni** the jarul is **due** for its photo)
  - 16 actions (2,330 verified points + 2 tree checks = **2,340 points**, Canopy Keeper; 1 pending shade canopy = 25 provisional points)
  - owner membership of Hall Rooftop Crew
  - the **North plot** Boro rice field at the flowering stage
  - 1 simulated sensor ("Balcony node")
  - 3 notifications
- **Dates are relative.** Story dates are "days ago" at load time, so the "1 tree due" state holds on presentation day.
- **The user is Nadia.** `useMe()` returns `u-nadia` with role `user`, so nothing is guest-restricted.
- **Server data is cached-first** (`staleTime: Infinity`, no refetch on focus or reconnect). The caller passes `DEMO_POINT` to location-taking hooks.
- **The goal's zone is bound on the first scan.** Live zone ids depend on the scan, so the seeded goal starts as `zone_id: 'demo:asad-gate'`. The first `useZones` result in demo mode binds it to the **rank-1 zone**: its id, centroid and area. The name "Asad Gate block" is kept. `usePlan` stays disabled until the goal is bound.
- **Reset and switching back.** `reset()` wipes the `demo` namespace and reloads the story. `disable()` returns to the user's own namespace, which is never touched by the demo.
- **Outside Presentation mode**, Nadia still exists as a seed person. Her story actions feed her leaderboard row and Hall Rooftop Crew's totals, so the community numbers match the design either way.

## Notes for other prompts

- **V0-1:** keep `QueryClientProvider` above every screen. Write prefs only through `prefs-store`'s `setPrefs`, so the data namespace follows Presentation mode and `lang`. Map `GuestRestrictedError` to `requireAccount()`.
- **V0-2:** the client sends exactly `VerifyPhotoRequest`, `TreeCheckRequest`, `PlanRequest` and `AskRequest`. SSE events may omit `type` inside `data` (the `event:` name is used), but including it is fine. Errors should be JSON `{code, message}` so they aren't mistaken for "route missing". Ask expects `done.remaining_today`.
- **V0-5:** use `useLogAction` with `species_id` for `plant_tree`. The contribution card reads `useAction(id)`.
- **V0-6:** S16 uses `useLeaderboard` + `useRisingTeams`; S17 uses `useTeam` (with `tasks`, `evidence`, `activity`); S18 uses `useOrg`; S19 uses `useCreateTeam` + `useInvite`; `/join/[code]` uses `useTeamByCode` + `useJoinByCode`; Profile uses `useMyStats`, `useTrees` and `useTreeCheck`.

## Known gaps

- Single device only: teammates, other users' confirmations and cross-device sync are v1.
- Team and org "week" and "month" numbers for seed entities are generated (seed), not derived from activity.
- The demo goal keeps its story name ("Asad Gate block") even if the live scan names the zone differently. Change `zone_name` in `bindDemoGoalZone` if the presentation needs the OSM name.
- `npm run typecheck` currently also reports 2 errors in V0-2's `src/server/farm/alerts.ts` (`Hazard` doesn't include `'storm'` or `'disease'`), which is outside V0-3.
