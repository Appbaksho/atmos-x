## How to run

```bash
cd apps/web
npm run i18n:check                                  # exits 1 and lists missing keys per locale/namespace
npm run i18n:check -- --ns home,map --summary       # counts only
npm run i18n:check -- --strict                      # placeholder/glossary warnings also fail
npm run i18n:translate -- --dry-run                 # shows what would be sent (no key needed)
npm run i18n:translate                              # all namespaces, hi ar es fr pt id zh + fill bn/ur
npm run i18n:translate -- --ns landing              # e.g. after V0-9 adds landing strings
npm run i18n:translate -- --ns plan --locales hi,zh --force   # re-translate machine strings (human ones are still kept)
```

Other flags: `--effort low|medium|high` (default medium), `--batch-chars 6000`, `--concurrency 6`, `--model <id>` (default `OPENAI_MODEL_CHEAP`, which is gpt-5.4-mini).
The key is read from `.env.local` and is never printed.

**Rules the script follows:**
- **Which keys are sent:** keys missing from the target file, and keys whose English hash differs from the hash in the cache (the English changed).
- **Human text is never overwritten:** a key that is present in a file but has no cache entry counts as human text. This covers every existing bn/ur string, and any string you fix by hand in a machine file (as long as the English stays the same).
- **Batches:** about 6000 English chars per call. The call uses the Responses API with a strict JSON schema whose properties are exactly the batch keys (`ns.key`). Keys stay JSON in, JSON out, and array elements (`ask.sugg.*`) are sent per element.
- **Glossary:** "Atmos X", "Heat Score", "Ask Atmos", "NASA", "BMD", "PM2.5", "AQI", "OpenStreetMap" and "Open-Meteo" are enforced, so a translation that drops one is rejected. ERA5, DAE, OpenAI and similar terms are kept by instruction only. Each locale also gets a tone and register note (आप, vous, tú, você, Anda, 你, native digits for bn/ur).
- **Validation:** every translation is checked against its English by `compareMessages`:
  - The ICU syntax must parse, with apostrophe quoting handled. ASCII `'` is converted to `’` so `d'{n}` can't break ICU.
  - The placeholder names and types must match.
  - `select` options must match exactly.
  - Plural `=N` options must match. Plural categories may differ only as CLDR requires: ar may add two/few/many, zh may drop `one`, and `other` is always required.
  - `<tags>` and glossary terms must match.
  - **Retries:** failing keys are retried up to 2 more times, and the model is told the exact problems. A batch that hits `max_output_tokens` is split in half. Keys that still fail are left out, so English shows through. They are listed, and the script exits 1.
- `NOTES` in translate.ts gives the model context for ambiguous keys. It is used today for `ask.limit` and `ask.limitGuest`, where Hindi had swapped "{n} of {max}". Add a note there when a key's role is unclear.

## Cost

The full run translated 11,836 keys / 331k English chars in 173 batches and took 7 min. It used 175 calls: **413k input + 646k output tokens** (output includes medium-effort reasoning). All trials and re-runs together came to about 1.1M tokens.
At gpt-5.4-mini list prices of about $0.75/M input and $4.50/M output (check current pricing), that is **≈ $3.3 for everything**. Incremental runs cost cents: the last 9 keys took 6k tokens. `--effort low` roughly halves the output tokens.

## Layout sweep (390 px, real CDP viewport)

**Screenshot method:** `--screenshot` in headless Edge renders wider than `--window-size`, so every screenshot (including **en**) looks clipped on the right. That is an artifact, not a bug. I drove Edge over CDP instead (`Emulation.setDeviceMetricsOverride` 390×844, mobile) and measured `scrollWidth`, off-screen text and truncated text on each page.

**Pages checked:**
- ar and ur: community, profile, air, air/devices, farm/fields, settings
- hi: home, map, community
- zh: home, profile
- en: community, air/devices (for comparison)

**Results:**
- **No horizontal page overflow on any page** (`scrollWidth` = 390 everywhere).
- **RTL mirrors correctly:** tab bar, chevrons, leaderboard ranks, segment controls.
- **Fonts:** Noto Sans Arabic (ar), Noto Nastaliq Urdu (ur), Noto Sans Devanagari (hi) and Noto Sans SC (zh, after Poppins for Latin) all render.

Issues outside message files, to report:
1. `src/components/map/heat-map-screen.tsx:120` builds `${t('within')} ${radius} · …` by concatenation. Languages with postpositions (hi "500 मी के भीतर", ur, bn, zh "500米范围内") can't say "within 500 m" this way. I worked around it with noun labels ("radius"). The proper fix is a single ICU message, `"withinRadius": "Within {r} · …"`.
2. `src/components/air/air-parts.tsx:29`: the WHO marker label is `nowrap` and anchored near the band's end. It overflows the card by about 2 px even with the short "WHO 15" in ar/ur RTL.
3. `src/components/air/devices-screen.tsx:136`: the "vs area" tile label (`air.sensorsSub`, "Compared with the area estimate") is ellipsised at 390 px **in English too**. The tile is about 100 px wide, so the label should be a short key (e.g. "vs area").
4. ICU `#` and `{n}` numbers follow the locale's default numbering. ur (ur-PK) shows Latin digits ("1 سینسر"), while `f.loc` elsewhere shows Urdu digits. This is a cosmetic inconsistency. To fix it, pass pre-formatted strings, or set `numberingSystem` in next-intl `formats`.
5. **Name truncation:** long seed team names ("Mohammadpur Housing Greeners") and zone names ("Kaderabad Housing 6") are truncated with an ellipsis in every locale. That is by design, not a translation issue.
