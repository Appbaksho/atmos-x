## Slots for V0-4 (stable)

- **`import { FarmHome } from '@/components/farm/farm-home'`**: `FarmHome()` is F01. It renders its **own `<Screen tab bleed>`**,
  so render it as the whole page body, e.g. `if (prefs.farmer_mode) return <FarmHome />;`, and not inside another `Screen`.
- **`import { MyFields } from '@/components/farm/my-fields'`**: `MyFields({ onSelect? })` is the full F03 screen (its own
  `<Screen tab>`). It's used for `/app/farm/fields` and for the Map tab in farmer mode. `onSelect(field)` fires when a field is picked.
- `/app/farm/fields?add=1` opens the add-field form. FarmHome's "Add your field" button links there.

## What works

- **S26 Air** (`useAir(focus)`): PM2.5, the EPA 2024 category pill, the **AQI ring** in the AQI colour, the band bar with the
  marker and the WHO-15 tick, "× WHO", and source chips (with a "cached" chip when `meta.live=false`). It also has:
  - "My sensors": simulated sensors, labelled "Simulated device (v0)", with their difference from the area value. Nearby stations show if the server ever returns any.
  - A daily PM2.5 forecast chart with the WHO line, plus a warning note when the peak is above "moderate".
  - The clean-air plan, built from the server's `advice[]` codes (`server.advice.air.*`), with the "someone sensitive" toggle (local state only).
  - The "Connect my sensor" and "My devices" buttons.
- **S27 Devices** (`useSensors(air.pm25)`): one card per sensor (reading, AQI, difference from the area, online/waiting, model, simulated label) with remove (toast).
  It has empty, guest (account CTA) and loading/error states, and a note saying readings are simulated in v0.
- **S28 Add sensor**: build picker (4 options), outdoor/indoor, name, placement check (outdoor only), then "Start 7-day check".
  That calls `useAddSensor`, which stores `model = "<build> · <Outdoor|Indoor>"` with the device or focus location, then goes to S27.
  Guests get `requireAccount()`. The fake device keys and the mount photo from the mobile screen were left out, because they would be fake.
- **F01 FarmHome**: shows the first saved field. A guest, or anyone with no field, gets a **preview** instead: Boro at flowering, at the focus point, with a "Preview · not saved" pill and an "Add your field" CTA.
  The screen has:
  - the hero (crop, stage, live air °C from `useConditions`), a bell icon with an unread dot (`useUnreadCount`), and the place name linking to F03
  - the stage bar for the stage the user set
  - the most severe `useFarmAlerts` alert, with a level-coloured border, the hazard tag, the first action as "Do this today", and "See why & how" → F02 (`?field=<id>`). "+n more alerts" links to F03
  - the 5-day forecast (heat-coloured bars and rain) and the field-edge trees card → S14
- **F02 Alert** (`/app/farm/alert/[id]?field=`): navy hero (emoji or hazard icon, level pill, lead time, window), "Why this alert" (body + sources),
  "What to do" (numbered), "The one thing to do today" with "I've done it", and the DAE note for pesticide or fertiliser doses.
  An id that's no longer in the forecast shows "This alert has passed" with a link to F03. Without `?field=` it uses the first field, or the preview.
- **F03 My fields**: a MapLibre / OpenFreeMap map with one pill per field. Tapping a pill or a list row selects the field. Below the map:
  the field list, the navy "Field weather" card (air, feels-like, humidity, wind, 48 h rain, 5-day strip, glass source chips) and the "Alerts for this field" rows → F02.
  **Add/edit**: name, area stepper (acres), the 8 contract crops, the 5 stages, and a pin set by tapping the map, dragging the pin or "Use my location".
  A live "Alerts for this crop now" preview means **guests can preview alerts without saving**. Save for a guest opens `requireAccount('save your fields')`.
  Edit also has Remove.
- **Ask Atmos panel**: `BottomSheet desktop="right"` (a bottom sheet on mobile, a right drawer on desktop), with:
  - a **context chip** "<screen name> · <place or field>"
  - suggestion chips per topic (heat / air / farm / tree, from the existing copy; the tree chip uses the user's first tree name)
  - a photo attachment through **`<Camera>`** (V0-5's in-app camera, `seal={false}`), with a preview and a remove button
  - streaming through `useAskStream`: "Checking Atmos X data…" with a spinner appears straight away, then tokens arrive with a caret
  - **warnings first** in a deep-red strip labelled "Official:" for BMD or "Atmos X alert:" for local ones; `notice` events as warn notes
  - source chips, up to 2 action buttons that **navigate only on tap** (they close the panel and call `go(screen, params)`; S08 `zone_id` is mapped to `?zone=`), and 👍 feedback (local)
  - a Stop button while streaming, a "New chat" button, and error + retry
  - the counter "n of 30 messages today" (or "n of 5 guest messages") with the no-medical / no-pesticide-dose footer
  - over-quota sends: guests get `requireAccount()`, accounts get the "limit reached" toast

  The slot hides the panel when `prefs.ask_on` is false.
- **Ask context**: the panel always sends `context.lat/lng`, which is the focus point, or the field location for farm topics. It also sends:
  - `zone_id` / `tree_id` read from the route
  - `field_id` from `?field=`, or the first field
  - `visible.{screen, place, crop, stage, field}` (crop and stage drive the server's `get_farm_alerts`)

  **Any screen can add more** with
  `useAskContext({ context, visible, place })` from `@/components/ask/ask-context`. The latest mounted screen wins, and it clears on unmount.
  Air, F01, F02 and F03 already publish their numbers this way. **V0-4 / V0-5 / V0-6 can call it** too: for example, Zone could publish
  `{ context: { zone_id }, visible: { score, drivers } }`.

## Faked / simplified (honest UI)

- Sensors are simulated (V0-3), and every place that shows them says so. The mobile sensor blob map, the GEOS-CF 48 h chart, the indoor/outdoor
  numbers, the NDVI "satellite-detected" chart, the season-outlook climate risks (Kurigram normals), the beekeeper card and the device keys were **dropped**.
  They had no real data in v0. They were replaced by real data: the daily forecast, the stage the user set, and live alerts.
- `FarmField.area` is treated as **acres**, matching the seed's `area: 1.2`.
- "I've done it" on F02 and 👍 in Ask are local UI state only; nothing is stored.

## For other agents / the Integrator

- **V0-1 (kit bug):** `Photo` with `priority` can stay invisible. The eager `<img>` finishes loading before hydration, so `onLoad` never fires and
  the opacity stays at 0. I measured this on FarmHome's hero (`complete: true, opacity: "0"`). FarmHome now leaves out `priority` as a workaround.
  Fix idea: in `Photo`, check `img.complete` in a ref callback or effect.
- **maplibre-gl v6 worker:** under Turbopack the default worker URL 404s. `field-map.tsx` sets the same version-matched jsDelivr worker
  that V0-4's `map-view.tsx` uses, and `NEXT_PUBLIC_MAPLIBRE_WORKER_URL` overrides it. That CDN means the map needs internet anyway, since the tiles do too.
  Without WebGL the map shows a "can't load" note, and the list and "Use my location" still work.
- **V0-8:** new en strings in `air`, `farm` and `ask` need bn/ur and the other 7 languages. Watch these:
  - `ask.sugg.*` are **arrays** (read with `t.raw`); the `tree` entry keeps a `{name}` placeholder
  - `ask.screen.*` has one name per ScreenId, plus `tree`
  - `farm.home.more`, `farm.fields.sub` / `subArea` and `air.devSub` use ICU plurals
- One observation, unconfirmed: in a fresh browser profile, `/bn/app/...?demo=1` stayed a guest (no fields, "guest messages"),
  while `/app/...?demo=1` loaded Nadia's story. Worth a check in V0-1's `?demo=1` handling for prefixed locales.

## Known gaps

- FarmHome shows only the first field; there's no field switcher on F01. F03 has the selector.
- Season outlook / harvest dates need a sowing date, which isn't in the `FarmField` contract.
- The Ask chat resets when the panel unmounts. History lives in `useAskStream` state, and the panel stays mounted under the app shell, so in practice it survives navigation.
