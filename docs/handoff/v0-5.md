## Camera API (stable; V0-6 and V0-7 import it)

```tsx
import { Camera, type CameraCapture } from '@/components/camera';
<Camera open={open} onClose={() => setOpen(false)} onCapture={(c: CameraCapture) => …} overlay={<Hint/>} />
// CameraCapture = { blob, takenAt (ISO), lat, lng, accuracy?, source?: 'camera'|'file', width?, height? }
```

- **Live viewfinder.** Uses `getUserMedia` with the rear camera (`facingMode: environment`), plus a flip button when there are 2 or more cameras. It shows the lime brackets, a "GPS + time sealed" pill, and live coordinates and clock (`watchPosition` while the camera is open).
- **Shutter.** The frame is drawn to a canvas (≤ 1600 px). The GPS and time seal is burned into the bottom-left corner, and the result is encoded as a JPEG at 0.86. The user then picks Retake or Use photo, and `onCapture` fires only on Use photo. The camera does not close itself.
- **Fallback.** A file input (`accept="image/*" capture="environment"`) is used when the context is insecure (HTTP on a phone), there is no camera, permission is denied, the camera is busy, or `getUserMedia` hasn't started after 8 s. The picked file is decoded (EXIF orientation respected), resized and sealed the same way. `takenAt` is the file's `lastModified`. The "+" slot next to the shutter opens the same picker.
- **Optional props:** `seal={false}` (no burned-in stamp, e.g. for an Ask Atmos photo), `facing`, `title`.
- **Helpers.** `fileToCapture(blob, fix, date)` and `formatFix` are exported for anyone who needs the same resize and seal.

## Gaps and faked bits

- **The live camera was not tested on a device.** Headless only reaches the fallback path. Phones need HTTPS (DEV-CHECKLIST tunnel); on HTTP the fallback says so.
- **MapLibre worker.** maplibre-gl v6 resolves its module worker from `import.meta.url`, which Turbopack rewrites, so the default worker 404s. `geo-map.tsx` sets a version-matched **unpkg** worker URL, but only if none is set yet. V0-4's `map-view.tsx` sets a jsdelivr one. Both work, but maps need the CDN online and that file isn't cached by the SW. Override with `NEXT_PUBLIC_MAPLIBRE_WORKER_URL`.
- **Not ported.** The prototype's editable tap-to-place planting map, tree catalogue quantities, flowering calendar, and Cheapest/Balanced/Fastest budget mixes are not ported: the data contract has no source for them. The planting map shows the real OSM spots instead. Mobile's "Add 12 to plan" became "Log a planting".
- **Rough estimates.** Feasibility's solo/team/org hours (1.5 h per tree, 15 m² of coating per hour, 8 h per shade structure) are a labelled rough estimate.
- **Server-side issues I saw** (not mine):
  - Species `image_url`s from `/api/v0/species` are crops of the same sky photo.
  - Server notes print unformatted numbers ("2920 m²").
- **Presentation first-load race (V0-3).** On a fresh `?demo=1` load, the demo-namespace goals query can run before the story seed is written and cache `[]`. `use-goal-plan.ts` refetches twice (0.8 s and 2.5 s) as a mitigation. **V0-3 should invalidate `qk.goals('demo')` after the story load.**
- **RTL bidi.** In Urdu, `f.dC` and `f.money` strings get reordered ("C° 1.5−"). I wrapped them in FSI/PDI isolates (`components/plan/bidi.ts`) in my screens only. **This probably affects every screen; a fix in `f.dC`/`f.money` (V0-1) would be better.**
- **Strings.**
  - Action type titles and units, plus the client verification reasons (`unavailable`, `rate_limited`, `no_photo`, `teammate_confirmed`), live in `act.*`, not in `server.*` (`server.json` is V0-2's). `server.verify.*` is used first when present.
  - Level names fall back to a humanised code unless `profile.level.*` exists.
