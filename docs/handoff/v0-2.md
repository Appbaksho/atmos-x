# Handoff V0-2: server (live data modules, heat proxy, AI endpoints)

Branch `v0`, agent V0-2. Owns `apps/web/src/server/**`, `apps/web/src/app/api/v0/**`, `apps/web/scripts/{snapshot,probe,snapshot-lib}.ts` (+ tests) and `apps/web/src/i18n/messages/{en,bn,ur}/server.json`.

## What works

- Every `/api/v0` route in `V0_ROUTES` (16 endpoints) is implemented as a Next.js 16 route handler (`runtime = 'nodejs'`, `maxDuration` set, zod-validated input, `{ ...data, meta }` output, Cache-Control per endpoint). Dynamic params are awaited (`ctx.params` is a Promise).
- Errors are always JSON `{ code, message }`: `400 bad_request`, `404 zone_not_found` / `species_not_found`, `413 payload_too_large`, `429 rate_limited` (+ `Retry-After`), `502 upstream_unavailable`, `503 ai_unavailable` (tree-check only), `500 internal`.
- Live data: Open-Meteo forecast/archive/air/geocoding, Nominatim, Overpass (3 mirrors, hedged), NASA POWER (farmer drought input only), OpenAI (Responses API, openai v7).
- Heat proxy §5.1 exactly: bbox Overpass land cover (split into 2 parallel queries) → H3 res 11/10 cells clipped to the circle → 6×6 samples per cell with an R-tree + turf `booleanPointInPolygon` → fractions → `est_c` → Heat Score → top-quartile H3 clusters → names (nearest place ≤ 250 m, else biggest named road, else nearest place ≤ 1.5 km, else "Zone N") → ids `z-<h3 of centroid>-<radius bucket>`. Detail is stateless (zone index in cache, else re-scan around the id's cell).
- Fallback chain everywhere: fresh cache → live → stale cache → Dhaka snapshot (≤ 5 km of the demo point; zones ≤ 1 km) → synthetic H3 field (zones only). Anything not live has `meta.live = false`.
- Caching: in-memory LRU + JSON files in `apps/web/.cache/` (gitignored) with the §4.6 TTLs (weather 30 min, air 1 h, archive 30 d, Overpass 7 d, AI 7 d; scored scans 30 min). Concurrent identical calls share one upstream request.
- Protections: `atmos_device` cookie (minted + `Set-Cookie` if `src/proxy.ts` did not set it), Ask 5/day guest, 30/day user (hard cap 30), photo checks 20/day, cold scans 30/hour (warm scans free), global `AI_DAILY_REQUEST_CAP` (after it AI endpoints fall back: Ask → canned answer + notice, verify-photo → `pending/ai_unavailable`, explain → `why_text: null`, plan → deterministic, tree-check → 503).
- Snapshots: `npm run snapshot:dhaka` wrote 43 committed files to `src/server/snapshots/dhaka/` (en + bn; radii 300/500/1000; AI "why" for every 500 m zone and own/hottest zone of 300/1000; raw forecast/archive/air inputs so conditions/air/farm alerts recompute offline for any crop). `index.ts` there is generated (static JSON imports, so Next.js bundles them).
- Tests: `npm test` → 16 files / 94 tests (heat index, BMD bands, Bangladesh polygon, archive normal/trend, EPA AQI, §5.1 score maths + clustering + near-ties + what-if, tree ramp + projection, plan mix/feasibility, verify-photo rules + mocked OpenAI, rate limits, Ask helpers/SSE encoding, snapshot index).

## Commands

```bash
cd apps/web
npm run probe                 # calls every route handler in-process for Dhaka; prints status, ms, meta.live
npm run probe -- --no-ai      # skip /plan and /ask (no OpenAI calls)
npm run probe -- --photo      # also verify-photo + tree-check
npm run probe -- --base http://localhost:3000   # probe a running server over HTTP instead
npm run snapshot:dhaka        # re-record snapshots (morning of the demo); --clean wipes old files first
npm test && npm run lint && npm run typecheck
```

`probe` and `snapshot:dhaka` run `tsx --conditions react-server --env-file-if-exists=.env.local` (I changed those two scripts in `package.json`): the `react-server` condition makes `server-only` resolve to its empty module, so scripts import the real server modules without a dev server. Verified.

## Endpoints

All GET query params are strings; `lang` ∈ the 10 locales (default `en`); lat/lng validated; `radius_m` 100–1000.

| Endpoint | Input | Returns | Cache-Control | Notes |
|---|---|---|---|---|
| GET `/api/v0/conditions` | lat, lng, lang | `Conditions` | public 600 s | feels = NOAA heat index; `bmd_level` only in Bangladesh; `normal_c` = archive mean tmax DOY ±7; `anomaly_c` = today’s forecast max − normal; warnings `source:'local'` |
| GET `/api/v0/geo/reverse` | lat, lng, lang | `ReverseGeocode` | public 1 d | Nominatim, ≤ 1 req/s queue, cached 30 d per ~500 m cell |
| GET `/api/v0/geo/search` | q (≥ 2 chars), lang | `GeoSearchResponse` | public 1 d | Open-Meteo geocoding |
| GET `/api/v0/zones` | lat, lng, radius_m, lang | `ZonesScan` | private 300 s | cold scans count against 30/h; `scan.method` = `osm-proxy` or `synthetic` |
| GET `/api/v0/zones/[id]` | lang | `ZoneDetail` | public 600 s | `why_text` = AI (cheap model), cached per zone+lang 7 d; `history_kind:'air_temp'` (hot-season mean daily max, 20 y) |
| GET `/api/v0/zones/[id]/projection` | trees (100), roof_m2 (500), shade (0) | `Projection` | public 1 h | years = this year…2040 |
| GET `/api/v0/zones/[id]/planting-spots` | – | `PlantingSpots` | public 1 d | ground (open ground minus buildings), roofs ≥ 80 m², roadside tree pits every 25 m |
| POST `/api/v0/plan` | `PlanRequest` | `Plan` | no-store | deterministic quantities + AI structured details (`estimate: true`) |
| GET `/api/v0/species` | lat?, lng?, lang | `{ species: SpeciesSummary[], meta }` | public 1 d | Bangladesh (or no point): curated 20 trees + Madhabilata; elsewhere AI shortlist cached per country + 5° lat band |
| GET `/api/v0/species/[id]` | lat?, lng?, lang | `Species` | public 1 d | AI ids (`ai-<cc>-…`) need lat & lng |
| GET `/api/v0/nurseries` | lat, lng, radius_m (100–25 000, default 10 000) | `NurseriesResponse` | public 1 d | OSM + curated Dhaka list (≤ 15 km of the demo point); florists ranked lower |
| GET `/api/v0/air` | lat, lng | `Air` | public 30 min | `my_sensors: []`, `stations: []` (client fills sensors) |
| GET `/api/v0/farm/alerts` | lat, lng, crop (boro), stage (vegetative), lang | `FarmAlertsResponse` | public 30 min | alert `id` = `<rule>-<from date>` (use it for `/app/farm/alert/[id]`) |
| POST `/api/v0/verify-photo` | `VerifyPhotoRequest` (image ≤ 4 MB data URL) | `VerifyPhotoResult` + meta | no-store | 20/day/device |
| POST `/api/v0/tree-check` | `TreeCheckRequest` | `TreeCheckResult` + meta | no-store | 20/day/device (shared with verify) |
| POST `/api/v0/ask` | `AskRequest` | `text/event-stream` | no-cache | 5 or 30/day/device |

### Ask Atmos SSE wire format (for V0-3’s parser)

Headers: `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`. The stream starts with a comment line `: atmos` (ignore lines starting with `:`). Each event:

```
event: <type>
data: <JSON of the AskEvent object, including "type">

```

Order: `warning`* → `token`* → `sources` (once) → `action` (0–2) → `done` (always last, with `remaining_today`). `notice` (canned fallback / cap) and `error` (`ai_interrupted` mid-answer, `internal`) may appear anywhere before `done`. `action.label` is already rendered text in the request language (string), `action.params` e.g. `{ "id": "z-…-500" }` for S06, `{ "zone_id": … }` for S08, `{ "id": "<alert id>" }` for F02. A 429 is returned as JSON (not a stream) before streaming starts.

Example (canned fallback, bn):

```
event: notice
data: {"type":"notice","text":"এখন AI পাওয়া যাচ্ছে না, তাই আমাদের সর্বশেষ তথ্য দিয়ে একটি সংরক্ষিত উত্তর দেখানো হলো।"}

event: token
data: {"type":"token","text":"সাতমসজিদ "}

event: sources
data: {"type":"sources","sources":[{"id":"open-meteo","name":"Open-Meteo","url":"https://open-meteo.com","as_of":"…"},{"id":"heat-proxy","name":"Heat estimate: OpenStreetMap land cover + live weather"}]}

event: action
data: {"type":"action","action":{"label":"জোন দেখুন","screen":"S06","params":{"id":"z-8a3cf10ce3b7fff-500"}}}

event: done
data: {"type":"done","message_id":"msg_9c93f403549840bbacd3","remaining_today":4}
```

Ask behaviour: topic from the message (en/bn/ur keywords) or the screen; prefetch per screen (S06/S07 → `get_zone`, S26–S28 → `get_air`, F* → `get_farm_alerts`, S10/S11 → `get_species`, S12 → `find_nurseries`, heat → `get_conditions` + own zone when the scan is cached); warnings first (heat-wave warnings from conditions; danger-level farm alerts when farmer mode / farm topic; crop/stage read from `client_state.visible.crop/stage`, default boro/flowering); then `gpt-5.5` (reasoning effort low, `store:false`, encrypted reasoning carried between tool rounds) with 7 in-process tools, ≤ 3 tool rounds; history = last 6 turns; image → `input_image`. Failure before the first token → `notice` + canned answer filled with live numbers when available (prototype text only when nothing is available).

## Timings (measured from this machine; logs are printed as `[atmos] <label> <ms>`)

| What | Cold | Warm |
|---|---|---|
| 500 m scan (Gulshan, Overpass healthy, 2 parallel bbox queries) | **3.0 s** (Overpass 2.0 + 2.9 s, land cover 0.14 s) | **1–3 ms** in-process; ~250 ms on the first request incl. module load |
| 500 m scan (Mohammadpur, Overpass under load) | 18.5 s (one combined query, before I split it) | 1 ms |
| 300 m scan (res 11, 121 cells) | 22.6 s (one Overpass query slow) | 2–4 ms |
| 1000 m scan (192 cells, 20 k OSM elements) | 31 s via the 3rd mirror (now capped at a 30 s deadline) | 3–7 ms |
| Overpass overloaded (429/504 on all mirrors) | 25 s deadline → snapshot (≤ 1 km of the demo) or synthetic field | – |
| conditions | 0.9 s | 5–200 ms |
| zone detail (+ AI explain) | 1.3–3.9 s | 10–230 ms |
| plan (AI structured) | 4.8 s | – |
| verify-photo / tree-check (gpt-5.5 vision) | 3.9 s / 2.3 s | – |
| Ask, first token (bn, Home, "why is my area so hot?") | **1.5 s** with the own zone prefetched (full answer 7.5 s); 5.6 s when the model needed 2 tool rounds | canned fallback complete in 0.7 s |

The < 12 s cold target is met when Overpass is healthy (3 s); public Overpass mirrors were frequently overloaded during testing (429/504, private.coffee often > 25 s). The 7-day land-cover cache and the snapshots are what make the demo safe; run `npm run snapshot:dhaka` and open the map once before presenting so the scans are warm.

## Models

- `OPENAI_MODEL` = **gpt-5.5**: Ask Atmos (streaming + tools, reasoning effort `low`), verify-photo and tree-check (vision, structured output).
- `OPENAI_MODEL_CHEAP` = **gpt-5.4-mini**: zone "why" explanations, plan details (structured output), species shortlist outside Bangladesh.
- All calls use the Responses API with `store: false`; structured outputs use `zodTextFormat` (strict JSON schema) and are re-validated with zod. Client: `maxRetries: 1`, timeouts 20–30 s. About 50 OpenAI requests were used while building and testing this.

## Contract changes (additive only, `src/lib/data/types.ts`)

- `Hazard` gained `'storm' | 'disease'` (farmer engine: storm/cyclone, late blight).
- `Plan.care_plan?: string | null` (AI care plan).
- `VerifyPhotoResult.meta?: Meta` and `TreeCheckResult.meta?: Meta` (every response carries meta).

Other notes for V0-3 / porters:
- `ZoneDrivers.pop_density_km2` carries **buildings per hectare** (as the type comment says), flagged in `estimated` together with `dark_roof_pct` (assumed per country: BD 64 %) and `night_lst_c` (tonight’s min + 0.4 × land-cover term).
- `PlanAction.qty` is in the action type’s unit (`cool_roof` = per 10 m²); `Feasibility.needed.roof_m2` and budget lines are in m².
- Causes carry `adds_c` (°C each adds, daytime coefficients) for the "What each cause adds" card.
- Zone `name` is localised (`name:<lang>` from OSM, else the default name, else `server.zone.unnamed`).
- `/zones` sets `Cache-Control: private` (it may set the device cookie); hooks should pass `credentials: 'same-origin'` (default) so the cookie is sent.

## Known gaps

- **Overpass reliability** is the main risk: public mirrors were often overloaded (429/504). Mitigated by hedged mirrors, a 25 s (30 s for 1 km) deadline, the 7-day cache, snapshots and the synthetic field. Snapshots of planting spots for the 1 km zones failed (Overpass overload) and were not recorded; all other demo snapshots exist.
- Snapshots were recorded at night in Dhaka (land-cover terms × 0.4), so recorded Heat Scores are compressed (66–73, most zones flagged near-tie); daytime scans spread more. OSM zone names around the demo point are roads/housing areas (e.g. "Sher-E-Bangla Road", "Road 5"), not "Asad Gate". Recorded zone ids: 500 m own zone `z-8a3cf10ce3b7fff-500`.
- `OSM_USER_AGENT` in `.env.local` still has the placeholder `example.com` contact, which Nominatim rejects (403). The server then falls back to `AtmosX/0.1 (+https://github.com/Appbaksho/atmos-x)`; please set a real contact email (DEV-CHECKLIST).
- Curated Dhaka nurseries have approximate coordinates (the prototype only had distances); their `address` says so.
- Rate limits and the global AI cap are in memory (reset on restart; per server instance).
- Species details for curated trees: facts/growth text is English; names, care notes and season are en/bn/ur. AI species outside Bangladesh have no prices/images.
- No `stations` in `/air` (Open-Meteo CAMS is a model grid, not stations).
- Ask: the model sees prefetched/tool data and the client summary only; no web search. Answers in hi/ar/es/fr/pt/id/zh work (the model writes them), but server-rendered warning/notice/action text falls back to English until those locales get `server.json`.
- I did not run `next build`/`next dev` (per instructions); handlers were exercised in-process via `npm run probe`.
